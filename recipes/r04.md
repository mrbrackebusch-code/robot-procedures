## Retreat when two conditions agree

A robot with little shield and a nearby enemy needs another option. Add retreat, then give danger priority over the usual role decision.

## Build the third action

Create ``||functions(noclick):retreat||`` with one **Number** input named ``||variables(noclick):robot||``. Give that robot the **withdraw** order inside the function.

Use your existing action helpers as the construction model. The function name describes the job in your program; withdraw is the corresponding choice in the arena's order menu.

Keep ``||functions(noclick):attack||`` and ``||functions(noclick):protect||``. The planner will choose among all three jobs.

## Ask both danger questions

In ``||functions(noclick):planRobot||``, build a condition using ``||logic(noclick):and||``. On one side, compare ``||arenaLab(noclick):shield points of robot||`` **< 12**. On the other, compare ``||arenaLab(noclick):enemy distance from robot||`` **< 50**. Use the planner's ``||variables(noclick):robot||`` value in both sensors.

The condition is true only when **both** comparisons are true: the robot has fewer than 12 shield points, and the enemy is nearer than 50 distance units.

Look closely at the assembled example: each sensor replaces a number in a comparison, and the two completed comparisons fit into ``||logic(noclick):and||``. Keep **<**, rather than **≤**, in both comparisons.

> Low shield alone is not enough. This answer is true when low shield and a nearby enemy happen together.

#### ~ tutorialhint

```blocks
function planRobot(robot: number) {
    if (arenaLab.shieldPoints(robot) < 12 && arenaLab.enemyDistance(robot) < 50) {
        retreat(robot)
    } else if (arenaLab.isGuard(robot)) {
        protect(robot)
    } else {
        attack(robot)
    }
}
```

## Put danger first

Make the danger condition the **first** branch in ``||functions(noclick):planRobot||``. Use the native branch controls shown here to keep one selection with three outcomes.

If the danger condition is true, call ``||functions(noclick):retreat||``. Otherwise, if the robot is a Guard, call ``||functions(noclick):protect||``. Otherwise, call ``||functions(noclick):attack||``. Pass the planner's ``||variables(noclick):robot||`` into each call.

This order matters. A Guard with low shield and a nearby enemy takes the first branch and retreats. It does not also take the protection branch. Keep these choices in one ``||logic(noclick):if true then else||`` selection rather than making separate independent tests that can issue two orders.

## Predict the edges

Use **Practice current code** to predict, then inspect the current orders for these cases: low shield and near enemy; healthy shield and near enemy; low shield and far enemy. Ask which comparison changes between the cases.

Then inspect equality: shield **12** is not less than 12, and distance **50** is not less than 50. Either equality makes the danger condition false. A non-Guard in either equality case should engage; a Guard should use its usual protection branch.

If a robot retreats when only one danger comparison is true, inspect the connector between the comparisons. If a low, near Guard protects, inspect the branch order.
