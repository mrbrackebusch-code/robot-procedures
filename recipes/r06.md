# Reuse a policy with different inputs

### @explicitHints true

## Reuse a policy with different inputs

A Guard should begin retreating at a different shield limit. Keep one action policy, then let its calls supply the limit and whether protection is its job.

## Create one policy with three inputs

Create ``||functions(noclick):chooseAction||`` with **three inputs**, in this order: ``||variables(noclick):robot||`` of type **Number**, ``||variables(noclick):shieldLimit||`` of type **Number**, and ``||variables(noclick):guardDuty||`` of type **Boolean**.

In **Edit Function**, use **Add a parameter** → **Boolean** for the third input and name it ``||variables(noclick):guardDuty||`` before choosing **Done**.

Move the action selection from ``||functions(noclick):planRobot||`` into this function. Reconnect it to the new function's inputs. Call ``||functions(noclick):inDanger||`` with ``||variables(noclick):robot||`` and ``||variables(noclick):shieldLimit||``. If that answer is true, call ``||functions(noclick):retreat||``. Otherwise, test ``||variables(noclick):guardDuty||``: true selects ``||functions(noclick):protect||``; false selects ``||functions(noclick):attack||``.

The new Boolean input supplies the duty decision. It is a true-or-false value, not the text “true” and not a numeric robot ID. Pass the local ``||variables(noclick):robot||`` to every selected action.

> Each call must provide all three inputs: which robot, what shield limit, and whether protection is its duty.

> We pass the supplied limit into inDanger instead of fixing every call at 12.

#### ~ tutorialhint

```blocks
function chooseAction(robot: number, shieldLimit: number, guardDuty: boolean) {
    if (inDanger(robot, shieldLimit)) {
        retreat(robot)
    } else if (guardDuty) {
        protect(robot)
    } else {
        attack(robot)
    }
}
```

## Supply the policy inputs

In ``||functions(noclick):planRobot||``, keep a role selection. For a Guard, call ``||functions(noclick):chooseAction||`` with ``||variables(noclick):robot||``, **18**, ``||logic(noclick):true||``. For any other robot, call it with ``||variables(noclick):robot||``, **12**, ``||logic(noclick):false||``.

Use the third-input **true / false** dropdown in each call to choose its Boolean value. Match each value to its input in the assembled call. The first value identifies the robot. The second sets the shield limit. The third is the Boolean duty flag. A Guard can now retreat below 18 shield while another robot keeps the limit 12.

Keep the planning event calling ``||functions(noclick):planRobot||`` with the event's robot value. The arena still supplies one request at a time; your functions pass that value through the program.

#### ~ tutorialhint

```blocks
function planRobot(robot: number) {
    if (arenaLab.isGuard(robot)) {
        chooseAction(robot, 18, true)
    } else {
        chooseAction(robot, 12, false)
    }
}
```

```ghost
// P-02 DESIGN SNAPSHOT — not native PXT/Blocks verified.
// Same persistent MakeCode project; no world source is learner-authored.

function attack(robot: number) {
    arenaLab.issueOrder(robot, arenaLab.OrderMode.Engage)
}

function retreat(robot: number) {
    arenaLab.issueOrder(robot, arenaLab.OrderMode.Withdraw)
}

function protect(robot: number) {
    arenaLab.issueOrder(robot, arenaLab.OrderMode.Protect)
}

function inDanger(robot: number, shieldLimit: number): boolean {
    return arenaLab.shieldPoints(robot) < shieldLimit && arenaLab.enemyDistance(robot) < 50
}

function chooseAction(robot: number, shieldLimit: number, guardDuty: boolean) {
    if (inDanger(robot, shieldLimit)) {
        retreat(robot)
    } else if (guardDuty) {
        protect(robot)
    } else {
        attack(robot)
    }
}

function planRobot(robot: number) {
    if (arenaLab.isGuard(robot)) {
        chooseAction(robot, 18, true)
    } else {
        chooseAction(robot, 12, false)
    }
}

arenaLab.onPlan(function (robot: number) {
    planRobot(robot)
})

```
