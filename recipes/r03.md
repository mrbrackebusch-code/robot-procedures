## Give the planning task a name

The event already makes a choice. Move that choice into planRobot so the event can say which task should happen next.

## Name the larger task

Functions allow us to break up code into different sections. In doing so, we can separate distinct tasks, giving a distinct name for small tasks in your code.

Create ``||functions(noclick):planRobot||`` with one **Number** input named ``||variables(noclick):robot||``. Move the existing role selection from the event into this function. Keep the Protect and Engage branches in the same order.

Inside the moved blocks, reconnect the role reporter and both action-call inputs to **this function's** ``||variables(noclick):robot||`` parameter. The event's reporter belongs in the event; ``||functions(noclick):planRobot||`` receives the value it needs through its input.

## Replace the moved decision with a call

In the planning event, use the generated ``||functions(noclick):planRobot||`` call to replace the selection you moved. Pass the event's ``||variables(noclick):robot||`` into that call.

Follow a Guard's request: the event calls ``||functions(noclick):planRobot||``; that function asks about the role and calls ``||functions(noclick):protect||``; ``||functions(noclick):protect||`` submits the order. A function can call another function.

Make sure your code behaves **exactly** the same as before. You have named the planning task and changed the organization. You have not changed the combat rules or added a stronger order.
