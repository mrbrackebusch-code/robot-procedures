## Give one robot an order

A robot needs a plan. Give the action a name, then call it when the arena asks for that robot's next order.

## Name the job

Functions are a way to group sections of code to be run together. They are regularly used when writing code both to increase the readability of code, and to allow for reuse of common actions.

Your first function will be named ``||functions(noclick):attack||``. Its job is to give one robot the Engage order. Defining that job and asking it to run are two different parts of the program. You will build both.

In Blocks, open ``||functions(noclick):Functions||``. If ``||functions(noclick):Functions||`` is hidden, open **Advanced** first. The native menu shown here is where you create your own named work.

## Give the action a robot input

Use **Make a Function...** in ``||functions(noclick):Functions||``. In **Edit Function**, replace **doSomething** with ``||functions(noclick):attack||``. Under **Add a parameter**, choose **Number**, replace the default **num** with ``||variables(noclick):robot||``, then choose **Done**.

This input is a **parameter**: a name the function uses for a value it receives. Here the value identifies one robot. Its type is Number because the arena identifies robots with numbers; you pass the value along rather than choosing or calculating an ID.

The ``||variables(noclick):robot||`` reporter belongs to this function. Get it from the function's parameter, as shown. Creating a global variable with the same name would give you a different value source.

## Put the order inside the function

Inside ``||functions(noclick):attack||``, add ``||arenaLab(noclick):give robot order||`` and choose **engage**. Put the function's ``||variables(noclick):robot||`` input reporter in the order's robot socket, replacing its default value.

When we give this order block the ``||variables(noclick):robot||`` value, we are sending the order to the robot that was passed into ``||functions(noclick):attack||``. The definition describes what to do. It still needs a call before that order can run.

## Call the action from the planning event

Add ``||arenaLab(noclick):when robot needs a plan||``. This event runs when the arena asks your program to plan for one friendly robot. Its ``||variables(noclick):robot||`` reporter supplies that robot's identity.

After creating the definition, find the generated ``||functions(noclick):attack||`` call in ``||functions(noclick):Functions||`` and place it **inside the event**. Drag the event header's ``||variables(noclick):robot||`` reporter into the call's input, replacing the default number.

The event's value is the **argument** you send. The parameter inside ``||functions(noclick):attack||`` receives that value. Both are spelled ``||variables(noclick):robot||``, but each belongs to its own block. Follow the value from event → call input → function input → order.

## Try the missing call

Before changing anything, predict: if the ``||functions(noclick):attack||`` definition stays on the workspace but its call is removed from the event, will a robot receive Engage?

Temporarily disconnect the call from the event. Run **Practice current code** again and inspect the order result. Then reconnect the call, with the event's ``||variables(noclick):robot||`` value still in its input, and retry.

The definition can exist without being used. If the result reports a missing order, look first at the call and its connection inside the event. An intentional HOLD order and a missing order are different results.

## Take the same program into battle

Choose **Run all with current code** and compare the current orders with the Recipe 1 target: each requested robot engages. If an order is missing or sent to the wrong robot, return to Blocks, repair the connection and retry.

Then choose **Battles / replay**. Watch the robots follow your current orders in a changing fight. The arena handles movement, aim and combat; your event and function provide the decision. A valid Engage order can still lead to a lost battle. Retry is free, so use what happened to decide what to try next.

In AP CSP, a named piece of work like your function is also called a **procedure**. In this guide, we will keep using **function**, matching ``||functions(noclick):Functions||`` in the editor.
